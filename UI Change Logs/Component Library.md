- 2026-09-21 — **`tv-tab-group`**: fixed the active tab not moving on click when a page had set `.value` in script. Root cause was the custom-element upgrade race, not the click handling: `tv-components.js` loads the component files asynchronously, so any inline script that runs during parsing gets to the element first, and assigning `.value` on a not-yet-upgraded element creates an **own data property that permanently shadows the class accessor**. From then on `_onClick`'s `this.value = v` wrote that property instead of the attribute, so `attributeChangedCallback` never fired, `_sync()` never ran, and the underline stayed where it was while `tv-change` still dispatched — the panel switched but the tab didn't. `connectedCallback` now calls `_upgradeProperty('value')` (the same guard `tv-modal-card` already had), which deletes the own property and re-applies it through the setter. This was latent in **`prototypes/dashboard`** too, which sets `orgGrp.value` / `wsGrp.value` the same way — all 9 of its tab groups now report zero shadowed properties and every tab activates on click. Worth remembering for any future component with a reflected property: without that guard, a property set before upgrade is silently lost.
