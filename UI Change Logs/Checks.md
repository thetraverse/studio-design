# Checks — UI change log

Covers `prototypes/checks/` — `quality-checks.html` (synthetic sample grading), `checks-panel.html` (rubric checks) and the shared `checks.css`. Newest at the bottom.

- 2026-09-21 — Rebuilt both developer POCs as Studio prototypes: `.context/attachments/NK0AzK/sample-grading-mockup-2026-09-17.html` → `prototypes/checks/quality-checks.html`, `.context/attachments/Y6G55d/traverse-checks-panel-2026-09-21.html` → `prototypes/checks/checks-panel.html`. **Behaviour is like-for-like** — every scenario, state, modal, verdict rule and copy string is preserved; the POCs' data and logic layers were lifted verbatim into `quality-checks.data.js`, `quality-checks.logic.js` and `checks-panel.data.js` so the rebuilt views cannot drift from the numbers the POCs produced. This pass resolved UI only; UX changes are a second pass.
- 2026-09-21 — **One severity language across both surfaces**, defined once in `checks.css` as a six-tone table and mapped onto `tv-status-tag` kinds: pass → success, issue → error, attention → warn, mixed/contested → info, n/a → neutral, and **primary/indigo is never a severity**. Two decisions drove it: indigo stopped meaning "unstable" (it was the brand accent sitting beside real primary buttons in the same row) and moved to info sky; **orange was removed entirely** from the grading tab — out of date, draft and off-target are now the system's warn yellow. Tints derive from one foreground with `color-mix`, so adding a tone is one line. **Known collision for pass 2:** warn yellow now carries both "out of date" (grading) and "Improvement" (checks); those two meanings will need separating once the surfaces sit in one tab.
- 2026-09-21 — Everything now reads `design-system/colors_and_type.css`. The POCs' private ramps are gone — the grading tab's four reds and four greens collapse to one of each, and the checks panel's near-miss neutrals (`#F5F6FA`, `#1A1C2B`, `#E3E6F0`) become the real surface ramp with the accent corrected from primary-700 to primary-600. Zero raw hex remains outside the native-select chevron data URI, which is the same technique the dashboard and test-journey prototypes use.
- 2026-09-21 — Icons are Lucide from the vendored font (works under `file://`). The grading tab's 32 hand-drawn 2px SVG paths and its `●`/`○` tab dots are gone; the checks panel's entire Unicode glyph layer (`✕ ! ✓ ✦ ↺ ‹ › × ▶`) is gone. Improvement and "could not run" no longer share a glyph.
- 2026-09-21 — Components replace hand-authored copies: seven hand-rolled overlays and three `<dialog>`s are all `tv-modal-card`; five chip systems are `tv-status-tag`; buttons are `tv-button`; the editor tab strip is `tv-tab-group` (underline, matching the live test editor — the POC used a grey pill container, which this repo reserves for sub-navigation). The Sample/Category switch stays a pill group, which is the correct use of that pattern. Shared primitives (severity mark, level code, run chip, outcome bar, icon button, chevron, tooltip, table, toast, empty state) are defined once in `checks.css` and used by both files.
- 2026-09-21 — Design-system compliance: the grading tab's 4px left accent bars (banner, toast) and its coloured and inset shadows are gone; the checks panel's `translateY(1px)` card press and four-keyframe overshoot animation are gone (a fade + 8px rise on `--dur-base`/`--ease-std`); toasts moved to bottom-right with the full coloured border of §8.7; the auto dark mode and Source Serif 4 are removed; radii, spacing, type and motion are on the token ladders. Sentence case applied ("Sample view", "View full rationale", "Marking rationale", "AI-generated submissions"); "Rerun" standardised to "Re-run" across both files.
- 2026-09-21 — Structural fixes that keep behaviour identical: the sample modal's two prompts now **replace the card body** instead of stacking a second card on top of it (the modal-card rulebook rules stacking out) — Discard changes / Keep editing / Save changes, destructive-left and primary-right; delete confirmations use `primary-variant="danger"` so the primary keeps its right-hand position and renders red; the checks panel's tiles became `div[role=button]` so their own Fix issues / Revisit buttons are valid rather than buttons nested inside a button.
- 2026-09-21 — Defects carried in from the POCs and fixed: the grading tab's sample-name and target-mark inputs were live inputs with no handler, so anything typed was silently discarded (now written to the sample); the range slider announced `role="slider"` with `aria-valuenow` but bound pointer events only (arrow keys added, Shift for ×10); chevrons gained `aria-expanded`; tooltips are reachable on focus as well as hover; the checks panel's band open/closed state was keyed by the visible label string, so a copy change silently broke the toggles (now keyed by a stable id); its header chip had no issue state, so a panel with open issues still read amber "Needs review"; its "awaiting re-run" bar segment was the same grey as "nothing here"; and "Grading 1 samples" now pluralises.
- 2026-09-21 — **Combined the two surfaces into one file**, `prototypes/checks/index.html`, so you can click between them: one test-editor shell with tabs **Settings · Grading · Sample calibration · Checks**. `quality-checks.html` and `checks-panel.html` are removed — two files were two sources of truth. Sample calibration is the former Quality checks tab (its in-panel heading renamed to match); Checks is the former standalone panel. Nothing else changed: every scenario, modal, verdict rule and copy string is as it was, verified by driving the real UI (7 level + 3 points scenarios, 14 modal shortcuts, expand-all, category view, the fix queue, approve, the 42-entry decisions history, the group modal, and a tab round trip).
- 2026-09-21 — How the combination works, for whoever edits it next: each feature runs in its **own IIFE**, so the two POCs keep their own `state`, `render`, `counts` and `queue` without colliding (they had `esc`, `toast` and `render` in common). `esc`, `toast` and the tab router are shared at the top; each feature registers `{ title, render }` on `FEATURES` so the router can repaint the tab it shows. The two stylesheets' class namespaces are **disjoint and must stay so** — neither is scoped under a panel id, because each surface's classes are used inside its own `tv-modal-card` bodies, which render outside the tab panels. One toast host, one status ribbon, `?tab=calibration|checks` deep-links and is kept in the URL.
- 2026-09-21 — Two shell decisions the combination forced. **Settings and Grading are `disabled` tabs** rather than switching to an empty panel — they were inert in the POC and this tells the truth. **The shell title follows the active tab**, because the two POCs carry mock data for two different tests ("Database Design Fundamentals" / "Financial Reporting Case Study" vs "APC 2026 June Mock – Task C"); the Checks panel's own duplicate `<h1>` and eyebrow were dropped, and its status chip, last-checked, checks-run and "awaiting you" count all stay.
- 2026-09-21 — Fixed the Checks tab not showing as active when selected. Two changes: the underlying `tv-tab-group` upgrade-race bug (see the Component Library log) and, in the router here, setting the tab strip's **attribute** rather than its property — `setTab` runs during parsing, before the component scripts have loaded, so `tabs.value = tab` was creating the shadowing own property in the first place. Verified by clicking the real tabs rather than calling `setTab()`, which is what hid the bug the first time: single clicks both ways, five rapid switches, the `?tab=checks` deep-link, and disabled Settings/Grading correctly ignoring clicks.
- 2026-09-22 — The Checks tab now **opens not-checked** and has to be run, per the supplied design. New **run card** at the top of the panel, present in every state: title, status chip and the run button on one row, with the row beneath it swapping between the intro copy (before a run) and the run's meta line (after one). Before a run there is nothing else on screen — no tiles, no bands, no counts. The lifecycle is **not-checked → running → checked**: the chip reads `Not checked` (new `tv-status-tag` kind), then a busy `Running checks` chip, then `Needs review` / `Checked`; the button reads `Run checks` (play) → `Running checks…` (disabled) → `Re-run checks` (rotate-cw). A completion toast reports how many checks ran and how many items need review.
- 2026-09-22 — **The run button holds its position across all three states** — verified in the browser: right edge and top identical (1260, 294) and height constant at 36px through not-checked, running and checked. Only its width changes, because the label does. Getting there needed one fix: the "awaiting you" count was initially placed beside the button, and its appearance on first run pushed the button 20px left and 15px down. The count moved into the meta row below, so nothing in the head row varies in size between states. The intro also stays up during the run, so the card changes shape once (when results land) instead of collapsing and re-growing.
- 2026-09-22 — Supporting changes: the mock bar's `Revisit decisions` / `Fix issues` / `Open a check group` shortcuts run the checks first if the panel is still not-checked; `Reset decisions` became **`Reset to not checked`** and now restores the whole panel (findings, `lastCheckedAt`, run state) so the flow can be replayed from the top — verified that running again after a reset returns the original 2 open findings; and the mock note leads with the run step. **Known limitation:** the fixture is a single payload, so a re-run returns the same findings rather than confirming the fixes approved since the last run — the toast says so outright. Making `fix → re-run → passes` actually resolve needs a second set of results (or a derived one), which is a data-model decision rather than a UI one; happy to model it next.
- 2026-09-22 — **Both tabs now show the same test title** — the calibration one, which still tracks its rubric switch ("Database Design Fundamentals" / "Financial Reporting Case Study"). The shell title is a single shared `shellTitle` the calibration feature writes on render, replacing the per-tab `FEATURES[tab].title()` indirection, so the title no longer changes under you when you move between tabs. The checks fixture's own test name (`TEST_TITLE`, "APC 2026 June Mock – Task C …") is no longer surfaced anywhere. It appeared in one other place — a single finding's `subjectLabel`, shown on the fix modal's "where" line — so a `subjectOf()` helper re-points that at the shell title too; without it the tabs would still have disagreed about which test this is, just somewhere less obvious. Verified: no "APC 2026" string renders anywhere, the fix modal now reads "Database Design Fundamentals · introduction", and the title is stable across repeated tab switches and identical under both rubrics.
